# 设计：时间轴分轨道显示 + 文字自动检测生成框

## 1. 时间轴分轨道显示（MVP）

### 需求
所有框不再叠在一条轨道上，时间上重叠的框分行（轨道）显示。

### 方案
- **分配算法**：按 `start` 排序，贪心放入第一条"当前区间不与已有框重叠"的轨道（区间用 `b.span(total)` 展开后的生效区间）。不重叠的框共享一轨。
- **轨道数**：动态，上限 4 条。超过 4 条时剩余框全部画在第 4 条轨道上（半透明 + 提示），避免控件无限变高。
- **布局**：轨道高 14px、间隙 3px；控件总高 = 刻度区 10px + 轨道数 × 17px + 底部留白 6px，动态 `setFixedHeight`（约 33px～97px）。
- **交互不变**：点击/拖动 = seek；框颜色仍按列表序号 `color_of(i)`，与右侧框列表对应。

### 不做
- 轨道手动拖拽/排序、轨道命名、时间轴上直接拖框改区间。

## 2. 文字自动检测生成框（MVP）

### 需求
自动找出视频里的字幕/文字区域，生成擦除框：
- 单视频：主窗口一键"自动检测"，结果直接加入当前工程可编辑。
- 批量：批量对话框新增"自动生成工程"——选多个视频，逐个检测并保存 `.suberase.json`（**工程文件格式完全不变**），可直接用于批量擦除。

### 方案
- **检测器**：RapidOCR（det 检测），运行在一个**独立的 OCR 环境**（rapidocr + onnxruntime-gpu，已实测 GPU 可用；解释器由 `local_config.json` 的 `detect_python` 或环境变量 `SUBERASER_DETECT_PY` 指定），以**独立子进程脚本**方式调用，不往主环境装新包（避免依赖冲突，不动现有推理环境）。
- **流程**（`tools/auto_detect.py`，被 GUI / 批量脚本调用，输入输出走 JSON）：
  1. ffprobe 拿 fps / nb_frames；
  2. 按抽帧间隔（默认 **0.5s**，可调）用 ffmpeg 抽样帧到内存/临时 png；
  3. RapidOCR det 输出文字框（像素坐标 + 置信度）；
  4. **合并**：相邻采样帧中 IoU ≥ 0.3（或中心距 < 框高一半）的文字框合并为一个 Box，`start` = 首次出现帧，`end` = 最后出现帧 + 一个采样间隔（防漏尾）；
  5. Box 外扩 margin（默认 8px）后生成，落成标准工程 JSON。
- **断点续跑**：批量生成时，目标 `.suberase.json` 已存在的视频自动跳过。

### 默认参数（GUI 可调）
| 参数 | 默认 | 说明 |
|---|---|---|
| 抽帧间隔 | 0.5 s | 越小越准越慢 |
| 合并 IoU | 0.3 | 位置相近判定 |
| 外扩 margin | 8 px | 字幕边缘留白 |

### 不做
- OCR 文字内容输出、字幕跟踪/光流、掩码直接生成、检测精度评估面板。

## 3. 技术要点
- 检测子进程命令：`<OCR 环境解释器> tools\auto_detect.py --video <path> --step-sec 0.5 --out <json>`；GUI 用 QThread 包 subprocess（带 timeout），不阻塞界面。
- CUDA 推理不并发：自动检测与擦除不同时跑（批量流程里天然串行）。
- Windows 中文路径：抽帧/IO 全部走已验证的方案（PIL 存图、`cv2.imencode`，路径用绝对路径传递）。
